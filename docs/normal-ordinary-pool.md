# Ordinary pool source consumer

This is an inactive source contribution, not a financial readiness receipt.
The original pending-board candidate remains separately frozen. The inherited
schema2 Board correction also requires its separately qualified tool admission.

The normal collector accepts an optional immutable `ordinary_pool` configuration
only when the same value is bound to the member reader and original collector
qualification event. It contains `classifier_sha256`,
`pool_pre_expiry_blocks`, `maximum_exit_depth` and `minimum_confirmations`.
The classifier is the exact frozen ordinary source classifier, copied without
changes; its executable Python source hash is checked before use. Exit depth
cannot exceed12 and confirmations cannot fall below3. The expiry margin must
equal the owning native pool configuration. No source response selects code.

The private TARGET package adds exactly `owning_pool_inventory` and
`ordinary_source_classification` auxiliary originals alongside the existing CLN
originals. The original six source roles remain unchanged. Each observation
binds the exact new file hashes and classifier configuration. Their classification
is recomputed from the original complete SQL frame, native pool bytes and saved
Core originals. Classification grants no signatures, availability or money proof.

`authenticate_pool` then executes the existing admitted policy tool on each
original Full plus independent raw funding transaction. It compares exact coin,
amount, server/user key, expiry, D12, SDK exit depth and anchor contract, rechecks
the active confirmed funding and mempool-aware unspent output, and preserves
original request/output hashes. Native memory membership, SQL pool membership,
public ephemeral-key presence and native derived-key match must agree. Flux,
spent references, pruning, duplicate or excluded durable rows and customer-right
overlap hold. All pool leaves sharing an anchor allocate against one physical
output, which is counted only once in the declared operator backing member.

`join_pool_finance` consumes the already independently checked native fee epoch,
candidate bytes, miner-cost records and confirmed treasury assets. The exact
Pool permit must match the funding transaction. Positive miner costs must retain
the actual rounds payer and miners destination; authenticated zero fees create
no expense. Missing costs, arbitrary source labels, unmatched assets or permit
variants hold. These functions add neither assets nor customer liabilities and
give zero customer payment credit. The enclosing whole-boundary accounting,
native R/F, urgency, funding ownership and90-second deadline remain mandatory.
An authenticated durable signed carrier reserving a pool root also holds its
availability even while that carrier remains unbroadcast and Core reports the
root unspent. Its reservation does not become a paid miner expense.

The supported subset is an entirely confirmed, unspent, unallocated ordinary
pool. It does not resolve a partial pool already transferred to customers,
pruned historical rows, in-flight issuance or conditional history. The existing
collector still holds all nonempty round/participation domains: the current raw
SQL exports only a signed-tree byte count, not the full independently verifiable
tree/allocation commitment. A round resolver also needs original authenticated
participation intent, signed input/forfeit membership, replacement-output
ownership, confirmed funding or exact pending reservation, and consumed-right
lineage. Those inputs cannot be replaced with count fields or a native
`complete` flag. The separate transitive lineage proposal is not integrated here.

Consumer controls use explicit cryptographic stubs and synthetic raw wire/SQL
fixtures. They test independent join/refusal logic, not native qualification.
Actual e217 producer qualification, installed source/transport admission, the
current policy-tool binary and a genuine archived/live component join remain
separate requirements before activation. No wallet, signing, funding, runtime
installation, Store live or dispatch changes are performed by this contribution.
