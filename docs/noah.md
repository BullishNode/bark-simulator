# Owned Noah journeys

Noah integration is disabled until an immutable readiness manifest has independent, hash-checked observations for the owned HTTPS origin and CA trust, pinned backend and transport patch, healthy services, signet/server/SDK identity, declared phone identities and destinations, forwarding mode, and a separate capital allocation with fee caps. Live transport requires hostname-verified TLS and a pinned offline invoice verifier. Existing simulator allocations and permanently absent wallets are excluded.

The protocol uses `GET /v0/getk1`, Bitcoin signed-message ECDSA DER over the full issued challenge, `POST /v0/auth/login`, and bearer-gated registration, Expo registration and signed mailbox read authorization. Private signing material, read grants and tokens must go directly through private transport; they must never enter generic driver output capture. The native enrollment module requires a previously linked key at index0 and an online, declared phone. It does not derive another identity or expose a private key.

Enrollment has a separate immutable declaration and may use explicitly zero phone capital. It still requires independently checked owned transport, backend, signet/server/SDK identity and fresh phone identity. This permits authentic setup before payment qualification. Invoice creation, claims and payments require the positive capital and fee limits in the full payment declaration; unfunded enrollment never grants those permissions.

LNURL uses the same owned `/.well-known/lnurlp/{username}` path for discovery and the millisatoshi callback. Lightning requests omit Ark negotiation. Before dispatch, the adapter checks the actual BOLT11 signature, signet, exact amount, expiry, metadata hash and Lightning node identity, plus independently captured device/forwarder evidence binding that invoice to the frozen intended recipient. Metadata bytes are hashed exactly as received. A plain description cannot satisfy LNURL metadata binding; the pinned backend's plain-description paths remain compatibility failures. A backend-provided Ark address or a valid invoice signature alone cannot prove rightful recipient selection.

Original Expo invoice pushes create and submit an invoice, then return. Claims use the later original claim push. Durable original transaction IDs prevent duplicate invoice creation after lost replies. Payer intent, invoice hash and public proof are frozen before payment; full invoice bytes stay in a private, hash-checked artifact. A timeout holds the same intent/hash. It never fetches a replacement invoice or repeats a monetary dispatch. Node status, submission ACKs and outer wallet success remain insufficient to close recipient/refund, fee or ownership obligations.

Every observed protocol request/reply, signing result, original push delivery and native operation is retained with a UTC timestamp in protected artifacts on the owning host. Exact received body bytes are retained when supplied; decoded objects are explicitly labeled when wire bytes are unavailable. Duplicate, malformed and absent-phone deliveries remain available without opening a wallet. The public journal and trace contain checked artifact references and necessary outcome summaries, never raw phone payloads, bearer values, read grants, DER material or preimages. Private auditors check artifact hashes and actor/action context before reading them; public exports must exclude the protected artifact directory.

`simulator.noah_coverage.coverage()` preserves thirteen scenario rows and twelve LNURL journey rows, including required mid-swap disappearance, funded5→50→200 maintenance, and complete local S3 backup verification. All production journeys run on owned signet against the single fork-owned captaind, after readiness and separate capital are verified. Server interruptions and operator actions require declared fork-controlled maintenance windows. Reports retain mechanism, actual transport, result, evidence, fees and remaining liabilities per scenario/variant; failed and interrupted runs remain available. Local protocol/cryptographic tests do not qualify these journeys or stock mobile-binding compatibility.
